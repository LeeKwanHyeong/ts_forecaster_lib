# PatchTST 수정 전후 학습 비교

> 2026-11-15 삼성 브랜치에서 수행한 과거 실험 기록. 이번 v2 통합에서 재실행한 운영 성능 결과가 아닌 범위.

## 결론

- 기본 비교의 원 예측 WAPE: 160.588811% → 160.717437%. 이번 실험에서 수정 후 예측 성능 향상 확인 불가
- 동일 비음수 절단 후 WAPE: 12.599582% → 12.573464%. 원 예측과 구분해야 하는 소폭 차이
- 50 epoch 동안 5 epoch zero-loss 현상 미재현. 기본 LR의 기존 affine gamma는 약 0.947까지 감소하고 수정 후에는 1로 고정
- LR 1e-3 민감도 비교에서는 기존 gamma가 약 0.547까지 감소. 기존 native loss가 더 낮아도 고정 좌표계의 재구성 오차가 더 작다는 의미는 아닌 결과
- affine 수정의 의미는 정답 스케일 축소 경로 제거와 loss 신뢰성 확보. 이번 결과만으로 최종 예측 정확도 향상 또는 삼성 운영 원인 확정 불가

## 확인한 제한과 별도 문제

- 단일 예측 시작 주차, 64개 부품, 시드 3개 실험. 운영 성능 향상 또는 보고된 5 epoch zero-loss 현상의 재현을 보장하지 않는 범위
- 테스트 정답은 학습/모델 선택에 미사용. 최소 검증 loss 체크포인트를 각 코드의 원래 정책대로 선택
- 기존 `_clone_cfg_disable_spike`가 얕은 복사본의 중첩 설정을 바꾸면서 원본 `spike_loss.enabled`도 False로 변경하는 문제 확인
- 다만 이번 `LossComputer`는 지정된 `SpikeWeightedHuberLoss` 객체에 계산을 위임하므로 해당 손실 객체 자체가 꺼지는 것은 아님. Spike ON/OFF 단계의 수학적 차이는 별도 검증 필요
- 원본 코드, 원천 데이터, 운영 artifact, DB 및 Runtime 변경 없음. 기존 미커밋 개발 작업 보존
